## 🐛 开机自启指错了文件 —— 拆模块那次的静默破坏

用户报「桌宠又**不跟随软件启动**了」。查注册表：

```
DSH-Pet = "pythonw.exe" "...\desktop-pet\pet_system.py"
                                           ^^^^^^^^^^^^^^^
```

**指错了。** 入口是 `dsh_pet.py`，而 `pet_system.py` 只有常量和 winreg
封装 —— **没有 `main()`**。

开机跑起来是个瞬间退出、什么都不发生的进程。**不报错、不崩、不留日志**：
你看到的就是「桌宠不见了」。

---

### 根因

`4d3f645 refactor: 把 3300 行的单文件拆成 6 个模块` 把开机自启这段搬进了
`pet_system.py`，而里面写的是：

```python
return f'"{exe}" "{os.path.abspath(__file__)}"'
```

`__file__` 于是从 `dsh_pet.py` 变成了 `pet_system.py`。

**同一次重构里，这行代码一个字都没改** —— 它只是搬了家，语义就变了。

---

### 修法：两件事

**① 修写入端。** 新增 `entry_script()`，明确指向 `dsh_pet.py`。

**② 修存量。** 光修写入端不够 —— 拆模块之后勾过自启的人，注册表里到现在
都还是错的。新增 `repair_autostart()`，每次启动查一遍：开着自启但命令不对
就重写。

> 实测：本机跑一次返回 `"fixed"`，改完之后用**注册表里那条命令原样**启动，
> 桌宠真的起来了。

---

### 🧪 测试 440 → 453

`tests/test_autostart.py` 13 条。**最关键那条不检查字符串**：

```python
def test_the_target_is_actually_an_entry_point(self):
    target = _script_of(S.autostart_command())
    self.assertTrue(_is_entry_point(target),
                    f"自启指向的不是入口（没有 __main__）：{target}")
```

它**去读那个文件**，确认里面有 `if __name__ == "__main__"`。

为什么这么测：字符串怎么写都能过，但「那个文件能不能跑起来」才是这个
功能唯一要紧的事。`4d3f645` 就是字符串看着没问题、指向的文件却不是入口。

**验证过它真能拦住**：把修复临时改回 `os.path.abspath(__file__)`，这条
立刻红，报的正是「自启指向的不是入口（没有 `__main__`）」。

顺手也测了 `启动桌宠.vbs` —— 它也指着一个脚本，同一个坑。

### 顺带

`set_autostart()` 里有个**重复的 docstring**（函数体中间又写了一句
`"""开/关开机自启。返回是否成功。"""`）—— 那不是注释，是个没人用的
字符串表达式。删了。

### 如果你已经装了旧版

**打开一次新版就行** —— `repair_autostart()` 会在启动时把注册表改回来，
不用重新勾选。
