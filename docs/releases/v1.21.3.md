## 🔧 换成 exe 之前发现：装进去的皮肤会随临时目录消失

准备把运行方式从「源码跑」换成 `DSH-Pet.exe`，先查了一遍 exe 版的数据落点。
发现一个**只在 exe 下才暴露**的 bug。

---

### 问题

`--onefile` 打包 → `sys._MEIPASS` 是**每次启动解压出来的临时目录**，退出就删。

```
app_dir()    = _MEIPASS                    (frozen)
assets_dir() = app_dir()/assets
skins_dir()  = assets_dir()/skins          ← 安装目标
```

`pet_skin_install` 把皮肤装到 `skins_dir()`，`discover_skins()` 也只扫它。

**结论：exe 版从宠物库装的皮肤，重启就没了。**

源码运行看不出这个问题 —— 那时 `app_dir()` 就是仓库目录，是持久的。
**所以它一直没暴露，直到要换 exe。**

---

### 改法

- `skins_dir()` → **`data_dir()/skins`**（持久的那个）
- 新增 `bundled_skins_dir()` = `app_dir()/assets/skins`（随包发的只读）
- `discover_skins()` 和 `CLAWD_THEME_DIRS` **两个都扫**

已有那 6 个皮肤还在 `assets/skins/` —— **两边都扫，不用迁移**。

---

### 验证

模拟 frozen（`sys.frozen=True` + 真的 `_MEIPASS` 临时目录）跑了一遍：

```
app_dir    = ...\FAKE_MEIPASS_aypu5d9j
data_dir   = ...\FAKE_EXE_DIR_bja7y0xc
skins_dir  = ...\FAKE_EXE_DIR_bja7y0xc\skins    ← 持久
bundled    = ...\FAKE_MEIPASS_aypu5d9j\assets\skins
发现 10 个皮肤                                   ← 随包的和装的都看见
```

---

### 🐛 顺带：一个测试在污染仓库

`TestSkinInstall.setUp` 的注释写着：

```python
# 改 assets_dir（唯一真实来源），不是 SI.SKINS_DIR 也不是 B.skins_dir
B.assets_dir = lambda: ...
```

**那句话在改设计之后就不成立了。** `skins_dir()` 现在来自 `data_dir()`，
所以它只改 `assets_dir` 时，安装会落到**真的** `data_dir()` 里。

实测：跑一次测试，仓库里多出 `skins/dup`、`skins/nested`、`skins/test-skin`；
第二遍跑直接报「皮肤 test-skin 已经装过了」。

改成同时 patch `data_dir`。污染已清掉。

> 这是本项目的老形状：**改了来源，所有"改那个来源"的地方都要跟着改** ——
> 而注释里那句「唯一真实来源」正是最容易让人不再检查的地方。

### 🐛 CI 也抓到一个（我自己的）

```
AssertionError: Lists differ:
[('pystray', '托盘图标')] != []
```

两个错：

**① CI 少装一个包。** `ci.yml` 里那句 `# pystray 是可选功能，测试里不碰`
在我加了依赖自检之后就不成立了。

**② 那条测试写错了。** 我写的是 `assertEqual(check_dependencies(), [])` ——
**拿机器状态当断言**。本地装了 pystray 所以绿，CI 没装所以红。

契约不是"列表为空"，而是 **缺的报、有的不报**。
