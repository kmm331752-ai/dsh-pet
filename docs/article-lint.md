# 我的桌宠读了我 279 条报错，发现六成是同一件事

先说结论。

我让桌宠扫了我**两个月**的 AI 编程会话——**86 个会话文件，279 条工具报错**。
归一化之后聚成 45 种，其中 17 种是反复出现的。

然后我看到这个：

```
  74 次  cannot edit <str>: file changed since it was read
  48 次  edit requires reading <str> first
  40 次  cannot modify <str>: file has not been read
   4 次  cannot overwrite existing <str> without reading it first
   2 次  cannot write <str>: file changed since it was read
```

**168 条，占全部报错的 60%。**

它们说的是同一件事：

> **编辑文件之前，必须先读它；而且读完之后，文件不能变。**

我以为自己在写代码。实际上我在跟一个前置条件反复搏斗。

## 所以它现在做什么

把你踩过的报错按**形状**聚起来：

```
Error: edit requires reading "G:\...\foo.js" first — read the file, then retry
        ↓
edit requires reading <str> first
```

路径变 `<path>`、引号串变 `<str>`、数字变 `<n>`、破折号后面的安慰话砍掉。

然后**你又一次踩到同一个形状的时候，她认得出来**：

> 又踩到这个坑：cannot edit… 74 次了

## 不装 DSH 也能用

说句实话：这个功能原来只对我自己有用。

它读的是 DSH 的会话日志 —— **只有装了 DeepSeek Harness 的人才用得到**。
别人从这篇帖子里下载 exe，装上，看到的是一个"普通的可爱桌宠"，
然后就卸载了。**差异化对 99% 的人不可见。**

所以加了一条数据源：**本地 git**。

开发者机器上遍地都是 git，而且不需要你做任何配置 —— 她自己在常见的
代码目录里找仓库，读 `git log`，然后给你这个：

```
找到 2 个仓库，最近看过 63 次提交。

· desktop-pet：`dsh_pet.py` 前后改过 31 次
· 2026-10-19 那天 `README.md` 被改了 12 次 —— 在跟它搏斗？
· 61 次提交里 19 次是 fix
```

**「同一个文件你一天改了 12 次」和「你踩过 74 次同一个坑」是同一类洞察** ——
不是"你提交了多少"，是"你反复回到同一个地方"。

只读 `git log`，不读代码内容，全部在本机。找不到仓库可以在设置里填路径。

## 三个我特意没做的事

**① 没有接 LLM。**

接个本地模型当然更"聪明"——它可以说「你经常忘记保存」，可以给你建议，
可以显得很懂你。

**但它会编。**

而「74 次」是真数出来的。这条管线只会说「这个形状出现了 74 次」，
因为 74 就在文件里。**错了你能去数，对了你也能去数。**

**② 没有存任何原文。**

会话文件里有我的提示词、我的代码、我的路径。

这个功能**一个字都不存**，只存形状。连她自己的气泡里也不放路径和文件名
——有测试守着（`test_bubble_has_no_path`、`test_state_file_has_no_path`）。

**③ 没有做成每次报错都提醒。**

同一个形状出现 **≥3 次**才算「反复」——一次两次是手滑。
而且**同一次运行里同一条只提一次**——一个循环里连报 20 次的话，
她不能变复读机。

这些都不是"我很有品味"，是**踩过之后加的** —— 每一条下面都压着一次真实的
事故，`AGENTS.md` 里逐条记着。

顺带说一句工程量：这堆东西现在有 **440 项测试**、CI 三层（单元 / 冒烟 /
端到端），外加一个跑 8 个模拟小时的长跑测试专门查内存和状态机卡死。

## 顺带抄了一个 20 年前的东西

翻开源项目的时候，我又把 [oneko](https://github.com/adryd325/oneko.js)（1331★ MIT）
看了一遍 —— 就是那只追着鼠标跑的猫。

它的核心只有三行：

```js
const diffX = nekoPosX - mousePosX;
if (distance < 48) { idle(); return; }        // 够近就别追了
nekoPosX -= (diffX / distance) * nekoSpeed;   // 朝光标走
```

**而我的桌宠只会看，不会来。** 光标跑到屏幕另一头，她只是把头转过去。

所以给她加上了。但我改了三处，因为 oneko **永远追** —— 那是它的 charm，
也是它出名地有点烦的原因：

| 加的限制 | 为什么 |
|---|---|
| **光标得在动** | 你不动她就不来 |
| **够近就不追** | 不会扑到光标上 |
| **追太久就放弃** | 不跟着跑到天涯海角 |

顺序是 **看 → 过来 → 再看一眼**（oneko 也是先出一帧 `alert` 再起步）。

> 一个诚实的技术说明：那 16 个方向的素材是**视线**，不是**走路**。
> 拿它们当走路循环会变成滑行 —— 身体帧不变、窗口位置在挪。
> 所以走路用真正的行走动画，**到位停下时**才用 16 个方向正对着你。

## 诚实的边界

**这些数字是我自己的。**

一台机器、一个用户、两个月。我写的是 Node/Vue/Python 项目，用的是一个
特定的 AI 编程工具（DeepSeek Harness）。换个人、换个工作，「60%」
完全可能不是六成。

**但方法是可以复用的**——这才是我想说的。

一个读过你全部工作记录的东西，能看到的东西，和你从工作台前面看见的
不是一回事。你记得的是「今天又卡了半天」，它数得出「74 次卡在同一个前置条件上」。
